# TASK-0022: iOS 26 / Safari 26 — Fix Oversized Layout and Horizontal Scroll

## Goal

On a real iPhone 16 running iOS 26.5 the application renders too large and
shows an unwanted horizontal scrollbar. The DevTools "iPhone 16 iOS 18"
simulator does not reproduce the problem because it uses the legacy viewport
model. iOS 26 / Safari 26 ships a redesigned browser chrome with a revised
viewport geometry. This task identifies every root cause and applies the
targeted fixes.

No new dependencies may be introduced. No business logic is touched.
The mandate of ≥ 80 % branch coverage must be maintained (no JS changes are
expected; CSS-only and one HTML change).

---

## Root cause analysis

### RC-01 — Viewport meta missing `viewport-fit=cover`

**File:** `src/index.html:5`

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

iOS 26 introduces a taller, floating browser chrome that changes how the
visual viewport intersects with the layout viewport. Without
`viewport-fit=cover` the browser applies a conservative inset that can make
`width=device-width` resolve to a value narrower than the physical screen
width — causing content sized to `100%` of the app container to overflow the
shrunken viewport rectangle.

**Fix:** Add `viewport-fit=cover` to the meta tag:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />
```

---

### RC-02 — `body` has no horizontal overflow guard

**File:** `src/css/styles.css` — `body` rule (line ~100)

No rule prevents the `<body>` itself from growing wider than the viewport.
Any single child that overflows (fixed-width element, wide SVG, long
unbreakable string) will silently expand `<body>`, producing a horizontal
scrollbar.

**Fix:** Add to the `body` rule:

```css
width          : 100%;
overflow-x     : hidden;
```

---

### RC-03 — `-webkit-text-size-adjust` is vendor-prefixed only

**File:** `src/css/styles.css` — `html` rule (line ~97)

```css
-webkit-text-size-adjust: 100%;
```

Safari 26 / WebKit on iOS 26 honours the unprefixed `text-size-adjust`
property. The prefixed-only declaration may be ignored, allowing the browser
to auto-inflate font sizes on narrow viewports — which manifests as "the
application is too large".

**Fix:** Add the unprefixed property alongside the existing prefixed one:

```css
-webkit-text-size-adjust: 100%;
text-size-adjust         : 100%;
```

---

### RC-04 — SVG chart has no CSS width, only `viewBox`

**File:** `src/js/chartRenderer.js` — SVG creation (line ~142)

The `<svg>` element is given a `viewBox` and `preserveAspectRatio` but no
CSS `width` or `height`. Without an explicit CSS width the SVG intrinsic size
falls back to the SVG default (300 × 150 px in most engines, but Safari has
historically differed). On iOS 26 / Safari 26 the chart can render at its
intrinsic size rather than stretching to fill its container, making it appear
oversized relative to the surrounding layout or causing horizontal overflow.

**Fix:** Set `width: 100%` and `height: auto` on the SVG element via
`setAttribute` in the `renderIntervalChart` function, immediately after the
`svg` element is created:

```js
svg.style.width  = '100%';
svg.style.height = 'auto';
```

---

### RC-05 — `.ops-add` has a `min-width` that can overflow narrow viewports

**File:** `src/css/styles.css` (line ~348)

```css
.ops-add {
  min-width: 220px;
}
```

On viewports narrower than ~280 px (which can occur on iPhone SE and on iOS
26 with safe-area insets applied) this `min-width` forces `.ops-bar` wider
than the viewport. The `@media (max-width: 640px)` block already collapses
`.ops-bar` to `flex-direction: column` but does not remove the `min-width`.

**Fix:** In the existing `@media (max-width: 640px)` block, set:

```css
.ops-add {
  min-width: 0;
}
```

(This is already present for `.ops-add` inside that media query — verify it
is there; add it if missing.)

---

### RC-06 — `.occ-row__gap` `min-width: 6rem` can widen rows past the viewport

**File:** `src/css/styles.css` (line ~714)

The gap badge introduced in TASK-0021 carries `min-width: 6rem`. On very
narrow viewports (or when safe-area insets reduce the usable width) this
fixed minimum can push the 4-column occurrence row grid beyond the screen
edge. The responsive override at `max-width: 640px` does not neutralise it.

**Fix:** Inside the existing `@media (max-width: 640px)` block, add:

```css
.occ-row__gap {
  min-width: 0;
}
```
