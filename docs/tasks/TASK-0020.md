# TASK-0020: Deep Code Review and Remediation

## Goal

Perform a full code review of all files in `src/js/` and remediate every
identified issue. The review covers four categories:

1. **Logic bugs and inconsistencies** — behaviour that is incorrect or
   contradictory between modules.
2. **DRY violations** — code that is duplicated across files and must be
   consolidated.
3. **Performance anti-patterns** — redundant computation and redundant I/O

   and missed modernisation opportunities.

Each finding below is specific to a file, a line range, and the exact change
required. The task is complete only when every item in the completion checklist

## Category 1 — Logic bugs and inconsistencies

### ISSUE-01 · Confidence threshold mismatch

**Files:** `prediction.js:49-53`, `uiController.js:419-422`,
`sessionIO.js:222-228`

`prediction.js::confidenceLabel` classifies a score as `'high'` when
`score >= 75`. The narrative text rendered in **both** `uiController.js` and
`sessionIO.js` reads "High confidence (≥70 %)" — a different boundary. The UI
confidence badge (CSS class) in `uiController.js::confidenceClass` also uses
`>= 70` as its high threshold.

The result is that scores of 70–74 are labelled as `'moderate'` by
`prediction.js` but displayed as a *high* styled badge in the UI. This is a
silent data-display inconsistency.

**Fix:** Align all three thresholds on a single value. The canonical thresholds
must live in `reportConstants.js` as named exported constants:

```js
// reportConstants.js
export const CONFIDENCE_HIGH_THRESHOLD   = 70;
export const CONFIDENCE_MEDIUM_THRESHOLD = 40;
```

Update every consumer to import and use these constants instead of magic
numbers:

- `prediction.js::confidenceLabel` — change `>= 75` → `>= CONFIDENCE_HIGH_THRESHOLD`.
- `uiController.js::confidenceClass` — replace inline `70` / `40`.
- `uiController.js::renderPrediction` confidence narrative — replace `"≥70 %"` /
  `"40–69 %"` strings with template literals referencing the constants.
- `sessionIO.js::buildPredictionSection` — same as above.

## Category 3 — Performance anti-patterns

### ISSUE-11 · `renderList` triggers 4× `loadRecords()` and 3× `computeStatistics()` per render cycle

**File:** `uiController.js:229-252`

`renderList` calls `loadRecords()` itself, then calls `renderStatistics()`,
`renderPrediction()`, and `renderChart()`, each of which independently calls
`loadRecords()` and either `computeStatistics()` or
`predictNext()`→`computeStatistics()`. A single user action therefore causes:

- 4 synchronous `localStorage.getItem` reads.
- 3 full passes through `computeStatistics()` (including 5 separate `reduce`
  iterations each over the interval array).

**Fix:** Refactor `renderList` to load and compute once, then pass results
down as arguments:

```js
export function renderList() {
  const listEl    = getEl('occurrence-list');
  const sectionEl = getEl('occurrences-section');
  if (!listEl || !sectionEl) return;

  const records = loadRecords();
  const stats   = computeStatistics(records);
  const pred    = stats ? predictNext(records) : null;

  applySessionMode(records.length > 0);

  if (records.length === 0) {
    listEl.innerHTML = '';
    sectionEl.classList.add('hidden');
    renderStatistics(null);
    renderPrediction(null);
    renderChart(records, null);
    return;
  }

  listEl.innerHTML = records.map((iso, i) => buildCardHTML(iso, i + 1)).join('');
  sectionEl.classList.remove('hidden');
  renderStatistics(stats);
  renderPrediction(pred);
  renderChart(records, stats);
  refreshIcons();
}
```

Update `renderStatistics`, `renderPrediction`, and `renderChart` to accept
their pre-computed arguments (`stats` / `pred` / `records`) rather than
calling `loadRecords()` and `computeStatistics()` internally. Their function
signatures change to:

```js
export function renderStatistics(result)            // result = computeStatistics output or null
export function renderPrediction(result)            // result = predictNext output or null
export function renderChart(records, stats)         // records = ISO[] already loaded
```

`handleExport` and `handleDownloadReport` similarly call `loadRecords()`,
`computeStatistics()`, and `predictNext()` independently. Consolidate to a
single `loadRecords()` → `computeStatistics()` → `predictNext()` chain.

### ISSUE-12 · `computeStatistics` makes 5 separate `reduce` passes over `intervals`

**File:** `statistics.js:143-144`, `162-163`, `198`, `200-202`, `204-206`

`sum`, `variance`, `mad`, `skewness`, and `kurtosis` are each computed with a
separate `reduce`. These can be merged into a single pass:

```js
let sum = 0, sumSq = 0, sumCube = 0, sumFourth = 0, sumAbs = 0;
for (const v of intervals) {
  const d = v - mean;   // deviation from mean (requires mean computed first)
  sum      += v;
  sumSq    += d ** 2;
  sumCube  += d ** 3;
  sumFourth+= d ** 4;
  sumAbs   += Math.abs(d);
}
```

Note: `mean` must be computed from `sum` in a first pass over `intervals`,
then the deviations computed in a second pass. This reduces 5 passes to 2
(which is the mathematical minimum for these statistics).

### ISSUE-20 · `Math.max(...intervals)` spread is unsafe for large arrays

**File:** `chartRenderer.js:127`

```js
const yMax = Math.max(...intervals) * 1.18;
```

`Function.prototype.apply` (which spread desugars to for built-ins) has a
call-stack argument limit (~65,536 in V8). For very long sessions this would
throw a `RangeError`. Use a reduce instead:

```js
const yMax = intervals.reduce((m, v) => v > m ? v : m, -Infinity) * 1.18;
```

### ISSUE-21 · `handleImport` uses callback-based `FileReader` instead of `File.text()`

**File:** `uiController.js:682-703`

The `FileReader` callback pattern is the legacy API. Modern browsers expose
`File.prototype.text()`, which returns a `Promise<string>`. Rewrite as an
`async` function:

```js
async function handleImport(file) {
  const text   = await file.text();
  const result = parseImportPayload(text);
  const fileInput = getEl('import-file-input');

  if (!result.ok) {
    setImportFeedback(result.error, 'error');
    if (fileInput) fileInput.value = '';
    return;
  }

  clearRecords();
  addRecords(result.occurrences.map((iso) => new Date(iso)));
  if (fileInput) fileInput.value = '';
  setImportFeedback('', '');
  renderList();
}
```
